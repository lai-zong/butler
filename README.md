# butler —— 可审计的记忆治理与自进化系统

> **一个常驻在电脑里的 butler。它记得你、理解你的生活节奏，承担生活 / 健康 / 学习 / 办公 / 代码等领域的任务；
> 执行与复核可追溯，而你对它记住的一切拥有完全的可视、可改、可撤销权。**

第九届传智杯 **AI WEB网页开发挑战赛** 参赛作品 · 官方方向 1（AI Agent 智能助手）

---

## 这是什么

市面上的 AI 助手普遍是**无状态**的：每次任务都从零判断，记不住你，也不会从经验里学习。
少数带"记忆"的产品则是**累加式**的：记得越多、注入的噪声越多，最后反而更不懂用户。

**"记性好"不等于"懂你"。**

本项目做的是**演化式记忆**：

- **有用的记忆被强化**——被反复命中、被验证有效；
- **无用的记忆渐进休眠、归档，但不删除**——在对的场景再次命中时自动唤醒；
- **全过程可视、可干预**——你能看到它正在淘汰什么、保留什么，也能手动调整。

而这一切建立在**事件溯源**之上：任何状态都可由事件流重放得到，所以每个判断都能追溯、每次回退都能精确重做。

> **核心主张：淘汰不等于删除，进化不等于突变。**

## 架构速览

```text
                    ┌──────────────────────────┐
                    │           用户           │
                    └────────────┬─────────────┘
                                 │
                    ┌────────────▼─────────────┐
                    │  butler（唯一对用户负责）│
                    │  · 记忆召回 / 约束注入   │
                    │  · 任务契约 / 执行       │
                    │  · 工具调用 / 桌面能力   │
                    │  · 监督复核 / 结论呈现   │
                    └────────────┬─────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        ▼                        ▼                        ▼
   本地记忆库              工具 / 文件 / 桌面          模型服务
```

**单管家，不设多仆人。** 任务由 butler 自己拆解、执行、复核；任务契约、工具调用与监督结论都写入事件流，可追溯、可回放。

## 四处创新（全部在记忆治理层）

| # | 创新点 | 解决什么 |
|---|---|---|
| ① | **分层反思** | 学得**对**——每个领域只在自己的历史上反思，作用域被结构性限制，一次错误反思不污染全局 |
| ② | **效果验证** | 学得**可验证**——每条记忆有适应度（使用频率 / 效果验证 / 证据强度 / 时效，减去冲突与误用惩罚），效果差自动降权 |
| ③ | **跨领域冲突裁决** | 学得**不矛盾**——多个领域建议冲突时，由 butler 统一发现并裁决 |
| ④ | **渐进式记忆演化** | 学得**久而不乱**——优胜劣汰，可观测、可干预 |

### 我们不做创新宣称的两件事

诚实起见，下面两点是**成熟模式 / 基本功**，本项目直接采用，**不声称是创新**：

- **多 Agent 编排**（一个主 Agent 调度多个子 Agent）是业界成熟模式；本项目**不采用多执行单元**，而是单管家 + 工具调用，因此不把它当作本项目创新。
- **程序化路径优先于模拟 UI**（优先调 API / CLI 而非截图点击）：主流 Agent 工具本来就这样做。

## 记忆分权：同一真相源 + 分层授权

| 类别 | 内容 | 边界 |
|---|---|---|
| **全局硬约束** | 过敏原、用药禁忌 | 受控写入；召回时强制注入，不参与休眠淘汰 |
| **全局共享事实** | 人际关系、作息、长期目标 | butler 可写；读取留审计记录 |
| **敏感域信息** | 心理咨询、健康细节、财务 | 默认隔离；跨域使用需用户逐次授权，授权按任务失效 |
| **领域记忆** | 领域偏好、原则、方法 | 在所属领域内使用；可审计、可撤销 |

**关键约束**：全局层只能由 butler 的受控写入路径维护，领域执行不得越权写入——保证真相源唯一。

**敏感域默认隔离**，跨域使用需用户逐次授权且**按任务失效**，授权与读取全部记入审计。

## 隐私与数据边界

**本地优先。** 记忆、会话与事件默认保存为这台电脑上的本地数据；没有云端账户，不上传完整记忆库。

**调用模型时，必要的当前对话与任务上下文会发送给模型服务商**；不会把 API Key 放进界面或导出文件。模型侧的数据处理受服务商条款约束。

使用节奏只记录本程序 Web 界面的页面、时间与“最近是否有操作”，用于查看自己的使用习惯；**不采集**其它应用、窗口标题、键盘输入、网页 URL、文件路径，也不记录对话、任务、工具、记忆或审查内容。

页面可见且聚焦时约每 60 秒产生一条心跳；可在控制台「使用节奏」暂停记录或清除统计，清除不影响会话、记忆与任务。

## 快速开始

```bash
# 环境要求：Node >= 20.11，pnpm >= 9
pnpm install

# 配置环境变量
cp .env.example .env.local
# 编辑 .env.local，至少填入 DEEPSEEK_API_KEY（默认 provider）

# 可选：OpenAI 兼容 / Ollama 本地
# MODEL_PROVIDER=openai
# OPENAI_API_KEY=...
# OPENAI_BASE_URL=https://api.openai.com/v1
# OPENAI_MODEL=gpt-4o-mini
# 或 MODEL_PROVIDER=ollama（本地端点默认 http://127.0.0.1:11434/v1）

# 类型检查 + 测试
pnpm typecheck
pnpm test

# 开发服务器（首次编译完成后自动打开浏览器，并显示启动动画）
pnpm dev

# 指定端口 / 不自动打开
PORT=3001 pnpm dev
BUTLER_NO_OPEN=1 pnpm dev
```

也可以双击 `启动.bat` 或运行 `butler web`：会等页面真正可访问后再打开浏览器，看到同一段启动动画。

**首次启动会要求设置本地登录密码**：单用户、没有用户名，设置后不能关闭；登录保持 7 天；设置密码时同时设置一个找回问题，忘记密码用问题答案重置。这是本机访问控制，不加密磁盘数据，也不是多用户隔离。详见 [本地登录](docs/local-auth.md)。

### 模型厂商

- `deepseek`：默认；支持流式叙述、工具、结构化输出。
- `openai`：OpenAI 兼容端点，当前只承诺**非流式主模型**。
- `ollama`：本地 OpenAI 兼容端点，当前只承诺**非流式主模型**；默认 `qwen3.5:4b`，可用 `OLLAMA_MODEL` 覆盖。

模型接入页只管理连接与模型目录，不再显示“当前正在使用哪个角色”。具体模型在功能页选择：

- 对话模型：输入框右下角按会话选择；
- 记忆抽取 / 记忆语义嵌入 / 记忆召回重排：记忆页 →「模型设置」；
- 知识库检索模式 / 知识库嵌入 / 知识库本地重排：设置 → 知识库 →「检索设置」。

记忆和知识库各自保存角色绑定与索引，不共享同一套向量空间。后端 `/api/model` 继续提供连接、验证和记忆角色操作；知识库单独使用 `/api/knowledge/retrieval`。

模型接入会同时列出随程序提供的本地模型（BGE 嵌入、bge-reranker 重排），它们是只读本地资产，不需要 Base URL 或 Key。外部重排目前是 OpenAI 兼容 LLM 精排，不是专用 rerank HTTP 协议；知识库重排固定使用本地 cross-encoder。

### 知识库检索

知识库使用独立检索域：

```text
字面检索：DocumentStore 的分词匹配
语义检索：本地 bge-base-zh-v1.5 / 远程嵌入配置
混合检索：字面优先，语义补足（默认）
可选重排：本地 bge-reranker-base cross-encoder
```

默认采用混合检索，理由是评测中它比纯字面和纯语义更稳；纯语义与字面模式仍可在知识库「检索设置」中切换。索引持久化在 `.butler-data/knowledge-index.json`，与记忆语义缓存分开。

### 评测（手工运行）

```bash
pnpm eval:recall:dev        # 记忆召回 dev（40 正例 + 10 负例）
pnpm eval:recall:test       # 记忆召回 held-out test（20 + 10）
pnpm eval:extraction        # 事实抽取 50 条
pnpm eval:documents         # 文档检索 30 条
pnpm eval:knowledge         # 知识库字面/语义/混合 100 条查询
pnpm eval:documents:qa      # 文档端到端 QA 30 条（真实模型 + 引用）
pnpm bench:events 100000    # 事件 JSONL 基准
```

2026-10-25 收尾实测与边界见 `docs/design/quality-closure-2026-10-25.md`；当前实现状态以方案 §19.3 为准。

## 原创边界声明

**本项目核心代码为团队独立实现。**

**自研部分**（详见方案 § 18 完整列表）：

1. 事件溯源会话内核（完整事件类型体系、进程内事件总线、重放与状态重建、因果链追踪）
2. 单管家任务执行层（任务契约、结构化任务分解、约束注入、工具调用、执行汇报归并）
3. 记忆分权系统（四类记忆分级 + 权限矩阵 + 敏感域逐次授权 + 全局层单一写入权 + 约束注入与读取审计）
4. 分层反思机制（领域反思 + butler 跨领域复盘；作用域隔离）
5. 渐进式记忆演化机制（适应度函数与 EMA 平滑、四态生命周期、休眠唤醒、种群竞争、防退化设计、演化可视化与人工干预）
6. 跨领域记忆冲突检测与裁决（硬约束自动拦截 / 软约束上报裁决）
7. 记忆治理界面（候选审核、版本历史、遗忘权、凭证授权）
8. 画像快照与成长对比
9. 操作记忆化执行（方法记忆 / 偏好记忆 / 环境记忆 + 执行验证 + 失败重规划）
10. 本程序使用节奏（页面心跳、聚合与会话化，不含整机观察）
11. 原生桌面控制工具（基于 pywin32 / pyautogui / mss 的独立实现）
12. 通用 MCP 客户端（多传输、服务器管理、独立权限策略）
13. 三层安全防护（输入注入拦截 / 记忆凭证隔离 / 动作分级拦截）
14. 产出物版本化与三方同步回退
15. 流式推理呈现层（字符级流式、按句边界增量翻译、状态可视化、错误边界）
16. 定时任务调度（错过补偿、退避重试、手动触发、额度熔断）
17. 强制单用户本地登录与数据迁移（导出导入、凭证隔离、遗忘权）

**借鉴的成熟模式与开源设计思想（仅思想，未复制任何代码）**：

- **"程序化路径（API / CLI）优先于模拟 UI"**：属 Agent 工具的基本实现方式，**不作为创新点宣称**

- 工具权限确认机制：参考上述项目的工具审批设计

**使用的第三方依赖**：Next.js、React、TypeScript、react-markdown、remark-gfm、Zod、Vitest、
