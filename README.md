# 管家式 AI —— 可审计的记忆治理与自进化系统

> **一个常驻在电脑里的管家式 AI。它记得你、理解你的生活节奏，把任务派发给生活 / 健康 / 学习 / 办公 / 代码等专职仆人；
> 仆人执行、管家监督，而你对它记住的一切拥有完全的可视、可改、可撤销权。**

第九届传智杯 **AI WEB网页开发挑战赛** 参赛作品 · 官方方向 1（AI Agent 智能助手）

---

## 这是什么

市面上的 AI 助手普遍是**无状态**的：每次任务都从零判断，记不住你，也不会从经验里学习。
少数带"记忆"的产品则是**累加式**的：记得越多、注入的噪声越多，最后反而更不懂用户。

**"记性好"不等于"懂你"。**

本项目做的是**演化式记忆**：

- **有用的记忆被强化**——被反复命中、被验证有效；
- **无用的记忆渐进休眠、归档，但不删除**——在对的场景再次命中时自动唤醒；
- **全过程可视、可干预**——你能看到它正在淘汰什么、保留什么，也能手动调整。

而这一切建立在**事件溯源**之上：任何状态都可由事件流重放得到，所以每个判断都能追溯、每次回退都能精确重做。

> **核心主张：淘汰不等于删除，进化不等于突变。**

## 四处创新（全部在记忆治理层）

| # | 创新点 | 解决什么 |
|---|---|---|
| ① | **分层反思** | 学得**对**——每个仆人只在自己领域的历史上反思，作用域被结构性限制，一次错误反思不污染全局 |
| ② | **效果验证** | 学得**可验证**——每条记忆有适应度（使用频率 / 效果验证 / 证据强度 / 时效，减去冲突与误用惩罚），效果差自动降权 |
| ③ | **跨领域冲突裁决** | 学得**不矛盾**——多领域建议冲突时，由管家统一发现并裁决 |
| ④ | **渐进式记忆演化** | 学得**久而不乱**——优胜劣汰，可观测、可干预 |

### 我们不做创新宣称的两件事

诚实起见，下面两点是**成熟模式 / 基本功**，本项目直接采用，**不声称是创新**：

- **Multi-Agent 编排**（一个主 Agent 调度多个子 Agent + 汇总）：LangGraph / CrewAI / AutoGen 等框架均有文档化实现。
- **程序化路径优先于模拟 UI**（优先调 API / CLI 而非截图点击）：主流 Agent 工具本来就这样做。

## 架构速览

```
                        ┌──────────────────┐
                        │      用户         │
                        └────────┬─────────┘
                        ┌────────▼─────────┐
                        │   管 家 (Butler)  │  ← 常驻，唯一对用户负责
                        │  · 全局记忆       │     唯一裁决者
                        │  · 行为观察       │
                        │  · 路由与派发     │
                        │  · 约束注入       │
                        │  · 校验与裁决     │
                        └────────┬─────────┘
     ┌──────────┬──────────┬─────┴────┬──────────┬──────────┐
     ▼          ▼          ▼          ▼          ▼          ▼
   生活       健康        学习        办公        代码
  平等提案者  平等提案者  平等提案者  平等提案者  平等提案者
```

**五个仆人完全平等，没有任何一个拥有对其他仆人的否决权。**

- 仆人只提交 `findings`（发现 + 证据），**不做裁决、不排序、不判定严重性**；
- 硬约束（如过敏原）由**管家校验层机械拦截**，不是某个仆人的权力；
- 软约束（如减脂期）冲突时**上报用户裁决**。

## 记忆分权：同一真相源 + 分层授权

不同仆人需要的不是"不同的记忆副本"，而是**不同的可见范围、写入权限与使用授权**。

| 类别 | 内容 | 管家 | 所属仆人 | 其它仆人 |
|---|---|---|---|---|
| **全局硬约束** | 过敏原、用药禁忌 | 读写 | 强制可见（只读）| 强制可见（只读）|
| **全局共享事实** | 人际关系、作息、长期目标 | 读写 | 可检索（记审计）| 可检索（记审计）|
| **敏感域信息** | 心理咨询、健康细节、财务 | 读写 | 读写 | **默认不可见**，需逐次授权 |
| **领域记忆** | 领域偏好、原则、方法 | 只读（可审计）| 读写 | **不可见** |

**关键约束**：全局层**只能管家写入**，仆人无写权限——保证真相源唯一。

**敏感域默认完全隔离**，跨域使用需用户逐次授权且**按任务失效**，授权与读取全部记入审计。

## 隐私立场

**我们不收集数据。** 没有邮箱、没有手机号、没有云端账户——账号只是本地标识，用来把记忆归属到你。

行为观察只采集**应用名称、起止时间与时长、应用类型、空闲状态**；
**绝不采集**窗口标题与内容、键盘输入、网页 URL、文件路径。

原始记录默认 7 天后自动清除，长期只保留聚合规律。用户可随时查看、关闭、删除。

> 这个「**主动舍弃清单**」比「我们采集了什么」更能说明立场。

## 原创边界声明

**本项目核心代码为团队独立实现。**

**自研部分**（详见方案 § 18 完整列表）：

1. 事件溯源会话内核（完整事件类型体系、进程内事件总线、重放与状态重建、因果链追踪）
2. 管家 / 仆人编排层（意图路由、结构化任务分解、约束注入、仆人结构化汇报、任务粒度回退）
3. 记忆分权系统（四类记忆分级 + 权限矩阵 + 敏感域逐次授权 + 全局层单一写入权 + 约束注入与读取审计）
4. 分层反思机制（仆人领域反思 + 管家跨领域复盘；作用域隔离）
5. 渐进式记忆演化机制（适应度函数与 EMA 平滑、四态生命周期、休眠唤醒、种群竞争、防退化设计、演化可视化与人工干预）
6. 跨领域记忆冲突检测与裁决（硬约束自动拦截 / 软约束上报裁决）
7. 记忆治理界面（候选审核、版本历史、遗忘权、凭证授权）
8. 画像快照与成长对比
9. 操作记忆化执行（方法记忆 / 偏好记忆 / 环境记忆 + 执行验证 + 失败重规划）
10. 行为观察与时间维度画像
11. 原生桌面控制工具（基于 pywin32 / pyautogui / mss 的独立实现）
12. 通用 MCP 客户端（多传输、服务器管理、独立权限策略）
13. 三层安全防护（输入注入拦截 / 记忆凭证隔离 / 动作分级拦截）
14. 产出物版本化与三方同步回退
15. 流式推理呈现层（字符级流式、按句边界增量翻译、状态可视化、错误边界）
16. 定时任务调度（错过补偿、退避重试、手动触发、额度熔断）
17. 轻量本地账号与数据迁移（导出导入、凭证隔离、遗忘权）

**借鉴的成熟模式与开源设计思想（仅思想，未复制任何代码）**：

- **Multi-Agent Supervisor 编排模式**：属业界成熟模式，本项目直接采用，**不作为创新点宣称**
- **"程序化路径（API / CLI）优先于模拟 UI"**：属 Agent 工具的基本实现方式，**不作为创新点宣称**
- Agent 循环与工具调用范式：参考开源终端 Agent 项目 **opencode** 的架构思路
- 会话持久化与任务编排：参考 **DeepSeek Harness** 的会话 / 任务模型
- 工具权限确认机制：参考上述项目的工具审批设计
- **记忆与凭证隔离设计**：参考 **Meta Muse** 公开披露的 Secure VM 理念
- **桌面控制工具的工具划分方式**：参考开源项目 **Windows-MCP**（CursorTouch）的设计思路；
  *代码为基于 pywin32 / pyautogui / mss 等通用库的独立实现，未复制其源码*
- 检查点式回退：参考交互式调试与版本控制系统的通用范式

**使用的第三方依赖**：Next.js、React、TypeScript、react-markdown、remark-gfm、Zod、Vitest、
pywin32 / pyautogui / mss / pyperclip 等。均以**依赖包**形式正常引用，**未修改其源码**。
